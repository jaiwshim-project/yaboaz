1. 가이드의 목적과 13단계에서의 위치

초기자료 정규화는 고객이 제공한 서로 다른 형식과 품질의 자료를 검증 가능한 증거 단위로 정리하는 과정입니다. 자료를 보기 좋게 정리하는 것이 아니라 이후 문제 정의, 현장 탐색, 온톨로지, AI 판단과 Agent 설계가 신뢰할 수 있는 근거 위에서 진행되도록 합니다.

01 고객 온보딩 → 02 초기자료 정규화·Evidence 관리 → 03 2A4 문제해결 → 04 현장 탐색 → 05 맞춤 인터뷰 → 06 온톨로지
이 자료는 누가, 언제, 어떤 목적으로 만들었으며, 무엇을 증명하고, 얼마나 신뢰할 수 있는가?
오래된 자료현재 사실로 오인하지 않도록 최신성과 유효기간을 관리합니다.
혼재된 의미사실·해석·가설·요구를 분리합니다.
잘못된 AI 판단Evidence ID와 출처를 AI 판단에 연결합니다.
구조 오류문제·객체·관계·규칙을 잘못 설계하지 않도록 검증합니다.

2. 핵심 개념

원시자료와 Evidence의 차이

업무 매뉴얼, 엑셀, 회의록, 녹취, 로그, 사고보고서, 이메일, 사진, ERP·CRM 데이터와 담당자 설명은 원시자료입니다. Evidence는 원시자료에서 추출한 내용 중 출처·시점·주장과의 연결·사실과 해석의 구분·신뢰도·원본 추적성을 갖춘 증거 단위입니다.

원시자료 → 분류 → 내용 추출 → 출처·시점 확인 → 사실·가설 분리 → 신뢰도 평가 → Evidence 등록

Evidence Driven

데이터만 믿는다는 뜻이 아니라 문서·관찰·인터뷰·시스템 데이터의 출처와 한계를 명확히 관리한다는 뜻입니다.

질문 1이 주장을 뒷받침하는 근거는 무엇인가?
질문 2그 근거는 어디에서 왔는가?
질문 3현재도 유효한가?
질문 4다른 자료와 교차 검증되었는가?

정규화의 범위

데이터베이스 정규화만이 아니라 파일명, 자료 유형, 날짜, 작성자, 조직명, 업무 용어, 단위, 상태값, 중요도, 신뢰도, 보안등급, 버전과 Evidence ID를 공통 의미 체계로 바꾸는 작업입니다.

3. 초기자료 정규화 8단계

01

자료 수집 범위 정의

프로젝트 목표·업무·기간·시스템·자료 소유자·수집 제외 범위·개인정보·외부 반출 제한을 확인합니다.

산출물자료요청 목록, 담당자, 기한, 사용 목적, 보안등급, 수집 제외 범위
02

원본 보존과 식별번호

원본은 읽기 전용으로 보존하고 복사본에서 분석합니다. 해시 또는 고유 ID, 업로드자, 업로드 시간, 새 버전과 변경 이력을 기록합니다.

EV-프로젝트-자료유형-연도-일련번호
예: EV-FN-LOG-2026-003
03

자료 유형과 메타데이터 분류

Evidence ID, 자료명, 유형, 출처, 작성자, 소유자, 작성일, 발생일, 수집일, 대상 기간, 업무, 문제, 보안등급, 개인정보, 버전, 검토상태를 부여합니다.

04

형식 정규화

파일명, 날짜·시간·타임존, 조직·업무 용어, 단위, 상태값을 표준화합니다. 원래 표현은 동의어로 보존하고 원본 값과 정규화 값을 함께 관리합니다.

FireNavi_대피관리_사고보고서_20260815_v1.0.pdf
정상·양호·문제없음 → 정상
고장·작동안됨·오류 → 장애
05

Evidence 단위 추출

문서 전체를 하나의 Evidence로 등록하지 않고 확인된 사실, 측정값, 사건, 반복 행동, 병목, 규정, 판단 기준, 예외를 작은 단위로 나눕니다.

06

사실·해석·가설·요구 구분

“센서가 오래되어 자주 오작동한다”를 사실·해석·가설·검증 필요·요구로 분리합니다.

07

신뢰도와 증거 수준 평가

출처 명확성, 최신성, 원본성, 객관성, 완전성, 교차검증, 문제 관련성을 평가합니다.

08

검토·승인·연결

Evidence를 고객 목표, 문제, 이해관계자, 업무, 온톨로지, 판단 규칙, Agent, 워크플로와 연결하고 담당자의 검토와 승인을 받습니다.

자료 충돌

매뉴얼, 시스템 로그, 인터뷰가 다를 때 하나를 삭제하지 않습니다. 충돌 주제, 자료별 주장, 잠정 해석, 위험, 확인 담당자, 확인 방법과 결정 상태를 기록합니다.

충돌 예시공식 매뉴얼은 2단계 승인, 시스템 로그는 3단계 승인, 현장 인터뷰는 긴급 시 메신저 선승인이라고 말한다면 공식·시스템·실제 절차의 차이를 별도 문제로 등록해야 합니다.

6. 자료 유형별 정규화

문서·보고서작성 목적, 작성자·승인자, 적용 기간, 공식본, 현재 버전, 인용 데이터 출처와 실제 사용 여부를 확인합니다.
엑셀·CSV필드 의미, 생성 시스템, 기준일, 단위, 코드값, 빈 값, 중복, 수동입력, 집계 기준과 개인정보를 확인합니다.
시스템·설비 로그생성 시스템, 서버·현장 시간, 이벤트 코드, 누락 기간, 보존주기, 자동·수동 입력, 재처리를 확인합니다.
인터뷰·설문대상 역할, 경험 기간, 직접 경험 여부, 질문 방식, 시점, 동의, 편향과 교차 검증을 기록합니다.
현장 관찰시각·장소·행동·소요시간·사용 화면·반복 여부를 사실로 기록하고 해석을 분리합니다.
사진·영상·음성촬영 시점, 장소, 촬영자, 목적, 편집 여부, 동의, 위치정보와 확인 가능한 사실을 기록합니다.
관찰 기록 예시
10시 15분 작업자가 장비 상태 확인을 위해 세 화면을 조회했고 같은 설비번호를 세 번 입력했다. 완료까지 7분 40초가 걸렸고 별도 엑셀에 재기록했다.
→ 해석: 시스템 간 데이터 연결 부족으로 중복 조회와 재입력이 발생하는 것으로 보임

9. 교육생 실습과 평가

교육생은 혼재된 원시자료를 분석해 Evidence Card를 만들고 신뢰도를 평가하며 문제와 온톨로지 요소에 연결합니다.

업무 매뉴얼 + 사고보고서 + 인터뷰 + 로그 + 사진 + 점검이력 + 충돌 자료
→ 인벤토리 → Evidence 15개 → 신뢰등급 → 문제 가설 3개 → 온톨로지 후보 → 추가 질문 5개

10. 품질 점검과 핵심 원칙

원본은 보존하고 해석은 분리한다
자료의 양보다 근거의 연결성이 중요하다
출처 없는 정보는 가설로 관리한다
인터뷰는 현장 신호로 보고 교차 검증한다
자료 충돌은 제거하지 않고 관리한다
AI 생성 결과는 Evidence와 구분한다
고위험 판단에는 Human Gate를 적용한다
Evidence는 다음 행동으로 연결한다
AI가 무엇을 말했는가보다, 어떤 Evidence에 근거하여 왜 그렇게 판단했는지를 관리하십시오.
최종 정의

초기자료 정규화와 Evidence 관리는 흩어진 문서·데이터·로그·관찰·인터뷰를 출처와 신뢰도가 확인되는 증거 단위로 변환하고, 이를 문제·온톨로지·AI 판단·워크플로·KPI와 연결하는 과정입니다.
