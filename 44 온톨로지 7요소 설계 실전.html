1. 온톨로지 7요소의 의미

YABOAZ에서 온톨로지는 단순한 데이터 모델이 아닙니다. 현장의 언어, 업무 흐름, 사람의 판단 기준, 시스템 데이터와 실행 행동을 하나의 의미 구조로 연결하는 실행 지식 구조입니다.

객체무엇이 존재하는가
사람·장소·장비·문서·업무·사건·자원
속성어떤 특징을 갖는가
위치·상태·등급·시간·수량·담당자
관계어떻게 연결되는가
소속·포함·사용·발생·영향·책임
상태지금 어떤 조건인가
정상·대기·위험·승인·완료·중단
이벤트무엇이 발생했는가
감지·요청·변경·승인·실패·완료
규칙어떤 조건이면 어떻게 판단하는가
기준·제한·승인·금지
행동무엇을 실행하는가
알림·추천·승인요청·배정·차단·보고
온톨로지는 AI가 현장을 이해하고 판단하며 행동하도록 만드는 실행 지식 구조입니다.
현장 언어 → 객체 → 속성 → 관계 → 상태 → 이벤트 → 규칙 → 행동 → AI 실행

3. 온톨로지 설계 10단계

01

도메인 범위 확정

핵심 문제·업무·사용자·데이터·AI 행동·제외 범위·KPI를 정합니다.

02

도메인 용어 수집

현장 표현, 매뉴얼, 화면, 엑셀, 로그, 인터뷰와 판단 용어를 모읍니다.

03

객체 후보 추출

현장에 존재하고, 반복되며, 상태 변화·판단·행동·KPI와 연결되는 대상을 찾습니다.

04

핵심 객체 선정

문제 관련성, 반복성, 상태 변화, 관계 중심성, 판단·행동·성과 연결성으로 보류와 선정 대상을 구분합니다.

05

객체별 속성 정의

ID·위치·시간·상태·담당자·위험도·권한·출처와 KPI 필드를 정의합니다.

06

객체 간 관계 정의

포함·관리·영향·발생·실행·승인·출처·성과 관계와 방향·다중성을 정합니다.

07

상태와 상태 전이

객체별 상태, 상태를 바꾸는 이벤트, 승인자, 기록과 KPI 영향을 정의합니다.

08

이벤트 정의

업무 시작·상태 변화·알림·승인·감사·측정을 발생시키는 사건을 정리합니다.

09

규칙과 행동 정의

조건·판단·행동·승인·기록의 형태로 판단 기준을 작성합니다.

10

AI·워크플로·MVP 연결

온톨로지 요소를 AI 질문, 입력 데이터, Human Gate와 실제 실행 행동에 연결합니다.

5. 이벤트·규칙·행동 설계

이벤트

이벤트조건상태 변화후속 행동
센서 감지센서값 임계치 초과센서 감지·구역 주의위험도 판단
위험 확인복수 센서 감지구역 위험승인 요청
승인 완료관리자 승인안내 승인완료알림 발송
경로 차단연기 감지경로 사용불가대체 경로 추천

규칙 작성 공식

조건 → 판단 → 행동 → 승인 여부 → 기록
규칙 예시복수 센서가 60초 이내 감지되면 위험도를 높음으로 판단하고 관리자에게 대피 안내 승인 요청을 보낸다. 승인 결과와 근거는 로그로 기록한다.

행동

알림위험 알림 발송
추천안전 경로 제안
승인 요청사람에게 판단 요청
배정담당자 지정
차단위험 경로 제한
보고사고 보고서 생성
업데이트상태 변경
실행대피 안내 송출

7. 품질 점검과 흔한 오류

명확성객체·속성의 의미가 분명한가?
중복성같은 의미의 객체가 중복되지 않았는가?
누락성판단·실행 요소가 빠지지 않았는가?
관계성객체 간 연결이 충분한가?
상태성중요 상태와 전이가 정의되었는가?
규칙성판단 기준이 조건문인가?
행동성규칙이 실제 행동으로 연결되는가?
추적성Evidence와 연결되는가?
오류수정 방법
객체·속성 혼동위험도는 구역 또는 경로의 속성으로 정의
이벤트·상태 혼동화재 발생은 이벤트, 위험은 상태로 분리
모호한 규칙“위험하면 알림” 대신 조건·대상·승인·기록 정의
행동 없음승인 요청·알림·배정·보고를 추가
관계 부족포함·연결·책임·출처 관계 정의
AI와 단절판단 질문과 입력 온톨로지 연결
객체 과다문제 해결·실행에 필요한 핵심 객체만 선정
